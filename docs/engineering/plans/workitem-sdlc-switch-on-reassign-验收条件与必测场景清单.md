## 逐条验收条件

### 验收 1 改派到不同数字人自动换绑并从头重启

- 现象：已绑定流程的工单改派给另一名数字人后，交付流程切换为该数字人的流程，并从新流程首步重新开始。
- 前置：工单 `W1` 已绑流程 `S1`、当前步骤非空；目标数字人 `A2` 生效版本绑定流程 `S2`，`S1 != S2`；两者同租户。
- 动作：以人工身份调用 `PUT /api/workitems/W1/assignee`，`assigneeType=AGENT`、`assigneeRef=A2`。
- 可观测结果：接口 `200`；`workitem.sdlc_id = S2.id`（`=`）；`workitem.current_step_id = S2` 的 `step_order` 最小步骤 id（`=`）；`workitem.assignee_ref = A2.id`（`=`）。
- 维度：正向；覆盖层级：接口+DB；覆盖用例：T01、T02；数据可复用：否（改工单绑定）；数据准备：需造（缺 autowonder 测试库连接、W1/A2/S1/S2 数据，测试阶段执行人，测试阶段开始时）。

### 验收 2 换绑后的首步取最小 stepOrder

- 现象：新流程首步不是创建时间最早或 id 最小的步骤，而是 `step_order` 最小者。
- 前置：流程 `S2` 至少两个步骤，`step_order` 分别为 1 和 9，且 id 顺序与 `step_order` 相反。
- 动作：同验收 1。
- 可观测结果：`workitem.current_step_id = step_order=1` 的步骤 id（`=`），不是 `step_order=9` 的 id。
- 维度：边界；覆盖层级：接口+DB；覆盖用例：T01；数据可复用：否；数据准备：需造（构造倒序 id 与 step_order 的流程数据）。

### 验收 3 同一数字人重派不换绑

- 现象：把工单重新指派给当前同一名数字人，流程保持不变。
- 前置：`W1.assignee_ref = A1`，已绑 `S1`，`A1` 生效版本当前绑定 `S2`（模拟数字人改版后的流程漂移）。
- 动作：`PUT /api/workitems/W1/assignee`，`assigneeType=AGENT`、`assigneeRef=A1`。
- 可观测结果：`workitem.sdlc_id = S1.id`（`=`，未变成 `S2`）；若进入重启分支，`current_step_id` 为 `S1` 首步（`=`）。
- 维度：逆向；覆盖层级：接口+DB；覆盖用例：T04；数据可复用：否；数据准备：需造（构造在线版本流程与工单绑定不同的 A1）。

### 验收 4 目标流程与当前相同不换绑但重置首步

- 现象：换到另一名数字人，但解析出的流程与当前流程相同，只重启交付，不产生流程切换。
- 前置：`W1` 已绑 `S1` 且当前步骤为 `S1` 中间步骤；`A2` 解析结果也是 `S1`。
- 动作：同验收 1。
- 可观测结果：`workitem.sdlc_id = S1.id`（`=`）；`current_step_id = S1` 首步（`=`）；`workitem_event` 无 `SDLC_SWITCH` 行（`=` 0 条）。
- 维度：边界；覆盖层级：接口+DB；覆盖用例：T05、A03；数据可复用：否；数据准备：需造。

### 验收 5 无生效版本时取任一版本

- 现象：目标数字人从未发布，仍能解析出其历史版本绑定的流程。
- 前置：`A2.online_version_id IS NULL`；其两个历史版本分别绑定 `S2`、`S3`。
- 动作：同验收 1。
- 可观测结果：接口 `200`；`workitem.sdlc_id` 为 `S2.id` 或 `S3.id` 中解析器实际返回者（`=` 与解析器返回一致）；不为空。
- 维度：边界；覆盖层级：接口+DB；覆盖用例：T06；数据可复用：否；数据准备：需造（未发布数字人及多版本）。

### 验收 6 生效版本已解绑 SDLC 时不回退历史版本

- 现象：目标数字人生效版本解除了流程引用，改派结果走 workType 默认流程，而不是历史版本流程。
- 前置：`A2.online_version_id` 指向版本 `V2`，`V2.sdlc_id IS NULL`；历史版本 `V1.sdlc_id = S2`；workType 默认流程 `SD`。
- 动作：同验收 1。
- 可观测结果：`workitem.sdlc_id = SD.id`（`=`），不是 `S2.id`；`current_step_id = SD` 首步（`=`）。
- 维度：边界；覆盖层级：接口+DB；覆盖用例：T07、T08；数据可复用：否；数据准备：需造（解绑生效版本 + 默认流程）。

### 验收 7 目标无流程且无默认流程时回退旧流程并继续交付

- 现象：目标数字人没有任何可用流程，改派仍然成功，工单继续使用原流程交付，不被阻断。
- 前置：`A2` 所有版本 `sdlc_id` 为空；workType 无 `is_default=1 AND status='ENABLED'` 的流程。
- 动作：同验收 1。
- 可观测结果：接口 `200`；`workitem.assignee_ref = A2.id`（`=`）；`workitem.sdlc_id = S1.id`（`=`，保持旧流程）；`current_step_id = S1` 首步（`=`）；无 `SDLC_SWITCH` 事件（`=` 0 条）。
- 维度：逆向；覆盖层级：接口+DB；覆盖用例：T09、A03；数据可复用：否；数据准备：需造（目标数字人无流程且删除该 workType 默认流程）。

### 验收 8 目标流程无步骤时回退旧流程

- 现象：目标数字人绑定的流程没有任何步骤，改派不崩溃、不把当前步骤写空。
- 前置：`A2` 生效版本绑定 `S2`，`S2` 在 `sdlc_step` 无 `is_deleted=0` 的行；`W1` 已绑 `S1`。
- 动作：同验收 1。
- 可观测结果：接口 `200`；`workitem.sdlc_id = S1.id`（`=`）；`current_step_id = S1` 首步且非 `NULL`（`=`）；无 `SDLC_SWITCH` 事件。
- 维度：逆向；覆盖层级：接口+DB；覆盖用例：T10、A03；数据可复用：否；数据准备：需造（空步骤流程）。

### 验收 9 跨租户目标数字人被拒绝且整体回滚

- 现象：改派到其他工作区的数字人失败，工单的经办人和流程都不发生变化。
- 前置：`A2.tenant_id != W1.tenant_id`；记录改派前 `assignee_ref/sdlc_id/current_step_id/version`。
- 动作：`PUT /api/workitems/W1/assignee`，`assigneeRef=A2`。
- 可观测结果：接口错误码 `AGENT_NOT_FOUND`（`=`）；`workitem` 的 `assignee_ref`、`sdlc_id`、`current_step_id`、`version` 与改派前完全一致（`=`）。
- 维度：权限；覆盖层级：接口+DB；覆盖用例：T11；数据可复用：是（失败不写库）；数据准备：需造（跨租户数字人）。

### 验收 10 空 assigneeRef 不进入换绑

- 现象：`assigneeType=AGENT` 但未传数字人 id 时，走既有参数校验，不触发流程解析。
- 前置：`W1` 已绑 `S1`。
- 动作：`PUT /api/workitems/W1/assignee`，`assigneeType=AGENT`、`assigneeRef=null`。
- 可观测结果：接口返回既有参数校验错误（`=` 与改造前同一错误码）；`workitem.sdlc_id = S1.id`（`=`）；无 `SDLC_SWITCH` 事件。
- 维度：边界；覆盖层级：接口；覆盖用例：T12；数据可复用：是（失败不写库）；数据准备：现成。

### 验收 11 未绑定工单首次交付行为不变

- 现象：没有绑定流程的工单首次交付，继续按既有首次绑定逻辑处理。

### 验收 12 运行中派发改派按 stop-then-start 切换

- 现象：工单已有运行中的交付时改派，旧执行先停止，再以新流程首步启动新轮次。
- 前置：`W1` 存在状态为 RUNNING 的 dispatch，已绑 `S1`；`A2` 解析为 `S2`。
- 动作：同验收 1。
- 可观测结果：改派后 `workitem.sdlc_id = S2.id`（`=`）；旧 dispatch 进入停止流程（`=` 终态 CANCELED 或被取消协议标记）；新 dispatch 的 `sdlc_step_id = S2` 首步（`=`）。

### 验收 13 计划开始时间在将来时先落流程、到点按新首步启动

- 现象：改派同时设置了未来开始时间，流程立即切换，但交付到点才启动。
- 前置：`W1` 已绑 `S1`；`A2` 解析为 `S2`；`scheduledStartAt = 当前时间 + 10 分钟`。

- 维度：一致性；覆盖层级：接口+DB；覆盖用例：T15；数据可复用：否；数据准备：需造（可控时钟或等待扫描周期）。

### 验收 14 MCP 已绑定工单传 sdlcId 仍被忽略
