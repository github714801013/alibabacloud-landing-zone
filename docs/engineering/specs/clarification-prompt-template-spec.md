# 需求规格：需求澄清会话提示词模板选项

- task_id：`clarification-prompt-template`
- 来源：`docs/engineering/plans/clarification-prompt-template-clarification.md`（用户已确认）
- 调研依据：`docs/engineering/plans/clarification-prompt-template-gitnexus-inquiry.md`
- 分支：`xiexiongkun/source-customization-v1.1.0`
- 性质：本地二次开发定制，需可随上游升级逐点重放
- 与既有规格的关系：本规格取代 `clarification-template-options-spec.md` 中「不做模板列表、下拉菜单、工作空间级自定义模板」的非目标，并取代 `clarify-default-squad-spec.md` 中「需求澄清不提供自定义提示词文本」的范围限制；「开始交付」仍不在本规格范围内。

## Problem Statement

需求澄清面板目前只有两条写死在前端 i18n 的提示词：首次澄清与再次澄清。所有工单、所有成员都只能使用这两段文本，空间无法沉淀自己的澄清方法；成员也无法针对当前工单临时换用另一种问法。现有「AI 默认值」只能配置默认小队、默认数字人和首次自动发送，无法配置「首次/再次澄清分别用哪段提示词」。

## Solution

在「设置 → AI 默认值 → 需求澄清」中增加提示词模板能力：

- 两个内置模板（首次澄清、再次澄清）继续作为出厂文案，但正文可由空间拥有者修改。
- 空间拥有者可以新增、编辑、删除自定义模板；自定义模板包含名称与正文，正文可为空。
- 首次澄清与再次澄清各有一个默认模板选择项；未配置时分别回退到对应内置模板，保持现有预填行为。
- 普通成员可以在本浏览器覆盖默认选择与模板正文，不能新增、重命名或删除共享模板。
- 澄清面板增加模板选择器，列出全部生效模板；用户选择后只替换当前输入，不自动发送、不按工单记忆、不写本地存储。
- 模板正文只支持当前工单号一个变量，与工单澄清会话的既有绑定配合使用；不新增工单级存储。

## User Stories

1. 作为空间拥有者，我希望在「AI 默认值 → 需求澄清」里看到首次澄清与再次澄清两个默认模板选择项，这样我能统一约定空间默认问法。
2. 作为空间拥有者，我希望两个选择项都列出全部内置与自定义模板，这样我可以跨状态复用同一段提示词。
3. 作为空间拥有者，我希望新增自定义模板时填写名称与正文，这样我可以沉淀团队自己的澄清清单。
4. 作为空间拥有者，我希望内置模板名称固定、不可删除，但正文可以修改，这样既有入口不会消失，文案又能按团队习惯调整。
5. 作为空间拥有者，我希望内置模板正文不能保存为空，这样默认预填不会意外消失。
6. 作为空间拥有者，我希望自定义模板正文可以为空，这样我可以用空模板表达「这个状态不预填」。
7. 作为空间拥有者，我希望删除被默认选择项引用的自定义模板时，系统回退到对应内置模板，而不是留下失效引用。
8. 作为空间拥有者，我希望把内置模板恢复到出厂文案，这样团队改坏后可以一键还原。
9. 作为普通成员，我希望在本浏览器覆盖默认模板选择，这样我不必接受空间默认。
10. 作为普通成员，我希望在本浏览器修改任意模板的正文（含内置与自定义），这样我可以按自己的习惯澄清。
11. 作为普通成员，我希望本地覆盖优先于空间版本，空间拥有者后续修改不会覆盖我的本地版本。
12. 作为普通成员，我希望把内置模板恢复为空间版本，把自定义模板恢复为空间正文，这样我可以撤销本地修改。
13. 作为普通成员，我希望在设置页看到每个模板是内置还是自定义、正文摘要是什么，这样我能快速找到要用的模板。
14. 作为普通成员，我希望打开工单澄清面板时，首次澄清自动带出「首次澄清默认模板」，已有结构化澄清结果时自动带出「再次澄清默认模板」，这样我不用每次手动选择。
15. 作为普通成员，我希望输入框已有内容时不被默认模板覆盖，这样我不会丢失正在输入的文字。
16. 作为普通成员，我希望在澄清面板里随时切换模板，选择后用该模板正文替换当前输入，这样我能临时换一种问法。
17. 作为普通成员，我希望面板里选择模板不会自动发送，也不会记住到工单或浏览器，这样它只是一次性填入动作。
18. 作为普通成员，我希望选择空正文模板时输入框被清空，这样我能明确得到空白输入。
19. 作为普通成员，我希望首次会话的 5 秒自动发送仍然生效，并发送当前默认模板内容；正文为空时不发送。
20. 作为普通成员，我希望在倒计时期间手动切换模板会取消本次自动发送，避免发出不是我最终选择的模板。
21. 作为普通成员，我希望模板正文里的当前工单号被自动替换，这样同一段模板可以跨工单复用。
22. 作为维护者，我希望模板数据复用既有 `system_setting`，不新增表、不执行 DDL、不使用 Redis，这样升级和回滚都不需要数据迁移。
23. 作为维护者，我希望新逻辑放在独立文件，上游文件只做最小接入，并有改动面清单与升级重放步骤。
24. 作为维护者，我希望读取到损坏或旧版本的模板配置时回退到出厂文案并记录日志，而不是让设置页或澄清面板报错。

## Implementation Decisions

### 1. 模板模型

- 内置模板固定两个，ID 分别为 `bootstrap`（首次澄清）与 `reclarify`（再次澄清）。名称由 i18n 提供且固定；正文未覆盖时使用现有 `workitem:clarification.bootstrapPrompt` / `reclarifyPrompt` 出厂文案。
- 自定义模板字段为 `id`、`name`、`content`。ID 由前端生成，格式 `custom-<uuid>`；名称去除首尾空白后 1–50 字符；正文 0–10000 字符。
- 自定义模板名称在空间内唯一（去除首尾空白后比较）；内置与自定义通过类型标签区分，允许名称相同。重复时保存被拒绝并提示。
- 模板正文只识别 `{{workitemId}}`，替换为当前工单号；其他占位符按普通文本保留，不引入模板引擎。
- 模板正文按纯文本处理，不渲染 HTML。

### 2. 存储与接口

- 复用 `system_setting` 分组 `CUSTOM_AI_DEFAULTS`，新增键 `clarify.promptTemplates`，`value_json` 保存一个 JSON 字符串。不新增表、不新增迁移、不使用 Redis。
- JSON 结构固定为 `version`、`builtin`、`custom`、`defaults` 四部分；`version` 当前为 `1`。`builtin` 只允许 `bootstrap` / `reclarify` 两个键，缺省表示使用出厂文案；`defaults` 缺省时分别回退到 `bootstrap` / `reclarify`。
- `GET /api/workspaces/current/ai-defaults` 的 `clarify` 增加 `promptTemplates` 对象或 `null`；`PUT` 接受可选 key `clarify.promptTemplates`，值为上述 JSON 字符串。既有 5 个 key 的格式与语义不变。
- 权限不变：GET 需要 `READ_ONLY`，PUT 仅空间拥有者；不新增接口，不改 `SystemSettingController` 与 `SystemSettingService.VALID_GROUPS`。
- 保存时校验：JSON 可解析、版本为 1、内置键合法、内置正文非空、自定义 ID 前缀正确且唯一、名称合法且唯一、正文长度合法、自定义数量不超过 100、`defaults` 引用的模板 ID 必须存在。任一失败返回参数错误，不写入。
- 读取时容错：JSON 损坏、版本未知、字段类型错误时，按空目录处理并记录告警，接口仍返回成功；`defaults` 引用不存在的 ID 时，读取侧回退到对应内置模板。读取侧不因历史脏数据报 500。
- 服务端校验后按固定结构重新序列化，避免空白与字段顺序造成无意义差异。
- 旧前端不发送新 key；新前端仅在模板目录或默认选择有改动时发送该 key，未改动时保持既有 5 项请求不变。

### 3. 解析与预填

- 模板只在工单澄清面板生效；其他 AI 对话入口不读取模板目录，也不显示模板选择器。
- 生效模板 = 两个内置模板 + 空间自定义模板。内置正文按「本地覆盖 → 空间内置正文 → i18n 出厂文案」解析；自定义正文按「本地覆盖 → 空间正文」解析。名称：内置取 i18n，自定义取空间名称。
- 生效默认（首次）= 本地 `firstTemplateId` → 空间 `defaults.first` → `bootstrap`；再次同理，回退到 `reclarify`。
- 本地选择引用的模板不存在时，跳过本地层，回退空间默认；空间默认仍不存在时，回退对应内置模板。
- 面板预填沿用现有条件：会话就绪、输入框为空、不在回复/恢复/加载中、结构化澄清结果已落定。已有结构化澄清结果时使用再次澄清状态；否则仅在 `turns === 0` 时使用首次澄清状态；其余情况不预填。
- 预填必须等待 AI 默认值查询落定：查询成功按空间 + 本地解析；查询失败或字段缺失按出厂内置模板解析。查询未完成时不预填、不启动自动发送倒计时。
- 预填只写入一次；用户已有输入时不覆盖；空正文模板保持空白。

### 4. 设置页交互

- 「需求澄清」卡片新增两个默认模板选择项，选项为全部生效模板；选择项始终有值，默认分别为首次澄清/再次澄清内置模板。
- 卡片内新增模板列表，展示名称、类型（内置/自定义）、正文摘要与操作入口；新增、编辑使用弹窗。
- 空间拥有者：可新增、编辑任意模板正文、删除自定义模板、修改默认选择、恢复内置模板到出厂文案；内置名称只读，内置模板无删除入口。
- 普通成员：可编辑任意模板正文、修改默认选择、把内置模板恢复到空间版本、把自定义模板恢复到空间正文；无新增/删除/重命名入口。
- 模板名称、正文、默认选择的修改先在页面内暂存；点击页面既有「保存」按钮时统一提交。弹窗「确定」只做校验并回到页面，不单独发请求。
- 拥有者保存走既有 PUT：原有 5 项 + `clarify.promptTemplates`（本次有模板改动时）。成员保存只写 `aw:clarify-defaults:local`，不调用 PUT。
- 本地覆盖按字段生效：未出现=跟随空间；`firstTemplateId` / `reclarifyTemplateId` 有值=覆盖选择；`templateContents[templateId]` 有值=覆盖正文。本地不能覆盖名称，不能新增模板。
- 恢复语义：拥有者恢复内置模板到出厂文案（移除空间覆盖）；成员恢复内置模板到空间版本（移除本地正文覆盖），自定义模板恢复到空间正文。页面级「恢复为空间默认」在清除小队/数字人本地覆盖的同时，清除本地模板选择与正文覆盖。

### 5. 澄清面板交互

- 在输入区增加模板选择器，列出全部生效模板；初始值 = 当前状态的生效默认模板。选择器状态判定：有结构化澄清结果时为再次澄清，否则为首次澄清；首次状态仅在 `turns === 0` 时执行预填，但选择器初始值仍取首次默认模板。默认值查询失败时仍列出两个内置模板；查询未落定时选择器禁用。
- 选择模板后用解析后的正文替换当前输入；空正文清空输入；不自动发送、不写 `aw:clarification-prefill`、不写本地存储、不写空间配置。
- 选择器只表示「最近一次填入的模板」，用户手动编辑输入后不改变选择器值；切换工单或会话时重置为当前状态的生效默认模板。
- 选择器在回复中、会话加载中、提交中、历史加载失败或身份恢复未完成时禁用，与输入框禁用条件一致。
- 手动切换模板取消正在进行的自动发送倒计时，且不重新计时。

### 6. 自动发送

- 沿用现有「首次会话 5 秒倒计时」的条件与取消条件：会话就绪、`turns === 0`、无结构化澄清结果、生效开关为开、不在回复/恢复/加载中。
- 新增两个前置条件：AI 默认值查询已落定；当前状态默认模板解析后的正文非空且输入框已预填。正文为空时不启动倒计时、不发送。
- 倒计时结束调用既有发送逻辑，发送当前输入（即默认模板正文）；发送失败仍按现有逻辑回填并提示。
- 不新增自动发送开关，不改变 5 秒时长，不改变手动取消的触发条件。

### 7. 数据流向与变动

```text
设置页（AI 默认值 / 需求澄清）
  GET /api/workspaces/current/ai-defaults
    -> owner：直接使用空间默认
    -> member：空间默认 + aw:clarify-defaults:local 合并
    -> 渲染两个默认选择项 + 模板列表
  owner 保存
    -> PUT /api/workspaces/current/ai-defaults
       items：既有 5 项 + { key: "clarify.promptTemplates", value: "<目录 JSON>" }（有模板改动时）
    -> system_setting(CUSTOM_AI_DEFAULTS, clarify.promptTemplates)
  member 保存
    -> 只写 aw:clarify-defaults:local，不调用 PUT

澄清面板
  GET /api/workspaces/current/ai-defaults
    -> 合并本地覆盖 -> 解析生效模板与当前状态默认
    -> 满足现有预填条件时，用默认模板正文预填
  用户在面板选择模板
    -> 解析正文 -> 替换当前输入（空正文清空）
    -> 不发送、不持久化
  发送
    -> 现有工单澄清会话接口，链路不变

存储：不新增表、不执行 DDL、不使用 Redis；不新增接口，不改变既有接口权限。
```

## 验收标准

1. 设置页「需求澄清」同时显示首次澄清与再次澄清两个默认模板选择项；两个选择项都列出两个内置模板与全部自定义模板。
2. 未配置模板目录时，两个选择项分别显示「首次澄清」「再次澄清」内置模板，澄清面板按现有行为预填对应出厂文案。
3. 拥有者保存模板目录后，其他成员新打开设置页或澄清面板能读取到空间模板与默认选择；拥有者自身也按空间默认解析。
4. 普通成员保存不调用 PUT；刷新页面或换浏览器后回到空间默认；拥有者保存后成员未覆盖的字段跟随空间变化。
5. 正文解析优先级为「本地覆盖 → 空间正文 → 出厂文案」；默认选择优先级为「本地选择 → 空间默认 → 对应内置」；逐层失效时正确回退。
6. 内置模板名称不可编辑、无删除入口；内置正文为空时保存被拒绝；拥有者点「恢复默认」后回到出厂文案；成员点「恢复默认」后回到空间正文。
7. 自定义模板名称必填、空间内唯一；正文可为空；拥有者可删除；删除后引用它的默认选择回退到对应内置模板。
8. 选中空正文自定义模板时，澄清面板输入框保持空白，不预填任何文本，自动发送倒计时不启动。
9. 首次澄清状态（无结构化结果且 `turns === 0`）预填首次默认模板；已有结构化澄清结果时预填再次默认模板；输入框已有内容时不覆盖。
10. 面板选择器初始值为当前状态默认模板；选择后正文替换当前输入；空正文清空；不自动发送、不写工单记忆、不写本地存储。
11. 面板选择器在默认值查询未落定、回复、加载或提交时禁用；手动切换模板取消正在进行的自动发送倒计时，且不重新计时。
12. 自动发送仍只在首次会话、无结构化结果、开关开时触发；发送当前默认模板内容；默认模板正文为空时不启动倒计时；其余取消条件与现有行为一致。
13. 模板正文中的 `{{workitemId}}` 被替换为当前工单号；其他占位符原样保留；模板正文不作为 HTML 渲染。
14. 读取损坏 JSON、未知版本或非法字段时，接口仍成功并回退出厂模板；写入非法 JSON、未知默认模板 ID、重复 ID、空内置正文、超长正文或重复名称时返回参数错误且不落库。
15. 旧前端不发送新 key 时既有保存行为不变；新前端仅在模板目录或默认选择有改动时发送该 key，未改动时仍只发送既有 5 项；新服务端返回的新字段对旧前端无影响。
16. 无新增表、无数据库迁移、无 Redis 依赖；既有 GET/PUT 权限行为不变。
17. 后端目录编解码与服务测试、前端纯函数/设置页/面板测试、构建与既有回归全部通过。

## Testing Decisions

- **好测试的标准**：只验证外部行为——接口契约与权限结果、纯函数的输入输出、组件在用户操作下的可见行为；不测私有方法、内部状态或实现细节。断言值来自规格与已知出厂文案，不由被测代码反推。
- **接缝一：后端模板目录编解码**。对模板目录的解析、校验、序列化做纯类单测；覆盖合法目录、缺省字段、非法 JSON、未知版本、重复 ID、重复名称、空内置正文、超长正文、非法默认引用。
- **接缝二：后端默认值服务**。扩展现有服务单测，覆盖 owner 校验、读取容错、写入校验、既有 5 个 key 不受影响。
- **接缝三：前端解析纯函数**。对生效模板合并、默认解析、本地覆盖、删除回退、变量替换做纯函数单测；参考 `aiDefaults.test.ts` 的组织方式。
- **接缝四：设置页组件**。扩展现有页面测试，覆盖拥有者/成员保存目标、模板列表与弹窗、内置/自定义权限差异、恢复语义、空正文保存、重复名称提示。
- **接缝五：澄清面板组件**。扩展现有面板测试，使用假定时器覆盖默认模板预填、状态切换、空模板、面板选择器填入、不发送、不持久化、自动发送与取消。
- **边界用例**：无模板目录；只有内置覆盖；只有自定义模板；默认选择指向已删除模板；本地选择失效；本地只覆盖正文；空间正文为空的自定义模板；查询失败回退出厂；旧服务端无新字段；输入框已有内容；倒计时最后时刻切换模板。

### 公共 API 影响、回滚与升级重放

- `GET /api/workspaces/current/ai-defaults`：响应新增 `clarify.promptTemplates`（对象或 `null`），加法变更；旧前端忽略即可。
- `PUT /api/workspaces/current/ai-defaults`：新增可选 key `clarify.promptTemplates`，值为目录 JSON 字符串；既有 key 的格式与语义不变。

- 无数据库迁移；`system_setting` 的既有唯一键可直接承载。
- 回滚：回退代码后旧服务端的 `ALLOWED_KEYS` 不含该键，已写入的数据行被忽略；旧前端不发送该键。无数据损坏、无 schema 回退。
- 升级重放：
  1. 拉取上游并确认新的 merge-base；对比改动表中全部上游文件。
  2. 按表重放每个 hunk；新增文件原样保留。

## Further Notes

- **与既有规格的关系**：`clarification-template-options-spec.md` 的「不做模板列表/下拉/工作空间自定义模板」非目标被本规格取代；其自动填入再次澄清模板的行为仍保留，作为「再次澄清默认模板」的默认值。`clarify-default-squad-spec.md` 中「不提供自定义提示词文本」的限制仅对需求澄清放开，「开始交付」仍按原规格不提供模板。
- **语言**：内置模板名称与出厂文案随界面语言；空间保存的内置正文、自定义名称与正文是用户输入的单一文本，不随界面语言切换。拥有者用哪种语言写，所有语言界面都显示该文本。
- **保存时机**：设置页的模板新增、编辑、删除与默认选择先在页面内暂存，点击页面「保存」统一提交；弹窗「确定」不单独发请求。这样模板目录与默认选择原子写入，避免两次 PUT 互相覆盖。确认版记录中的「模板编辑弹窗保存」在交互上细化为「弹窗确定只暂存，页面保存统一提交」；持久化目标、权限与数据形状不变。
- **已知取舍**：本地覆盖不跨设备；空正文自定义模板是「不预填」的唯一表达方式，不额外提供「不预填」选项；模板选择器只做一次性填入，不表示输入框与模板持续绑定。
- **升级注意**：如果上游未来提供同类模板能力，优先合并去重，保留本规格的存储兼容与本地覆盖语义；不要在上游核心中直接嵌入本地业务规则。
- 规格与确认版一致：数据流向、变动清单与前端交互规则以确认版为准，实现阶段不得增删已确认行为；实现细节（类名、方法名、组件拆分）可调整，但必须保持本文的行为契约与改动面边界。
