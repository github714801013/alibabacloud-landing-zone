# AutoWonder 0.9.0：OceanBase 定时任务能力兼容规格

## 问题陈述

AutoWonder 部署在 OceanBase CE 4.3.5.6 MySQL 模式后，定时任务表、字段和索引已经初始化，三个 Scheduled Task 开关均开启，但运行时能力仍为 V037_PARTIAL，已登录前端因此隐藏“定时任务”。

已取得浏览器实际响应：available=false、mode=V037_PARTIAL、clusterReady=true、reason=DATABASE_UPGRADE_REQUIRED。只读元数据检查确认，剩余五项误报对应四个时间字段默认值和一个 STORED 生成列；物理对象存在，不能通过重复初始化数据库解决。

## 解决方案

在现有 V037 schema 探测器的元数据读取层归一化已确认的 OceanBase 等价展示，保留真实结构、默认值、来源隔离和索引契约。修复后，完整基线应被识别为 V037_READY；在已批准的部署开关条件下，能力接口返回可用，前端沿用现有门禁显示入口。

2. 作为工作空间用户，我希望通过真实能力接口看到定时任务入口，而不是伪造前端状态。
3. 作为 MySQL 8 部署维护者，我希望现有标准元数据继续通过，不因兼容修改而退化。
4. 作为维护者，我希望整数显示宽度被视为展示信息，同时无符号属性仍被严格检查。
5. 作为维护者，我希望仅 datetime(3) 的已确认时间默认值展示差异被归一化，其他精度差异仍被拒绝。
6. 作为维护者，我希望生成列的重复默认值投影只有与生成表达式一致时才被接受。
7. 作为安全维护者，我希望错误的生成表达式、字段类型、可空性、索引唯一性和列顺序仍阻止能力开放。
8. 作为部署维护者，我希望权限不足和查询失败保持 fail-closed，而不是自动降级为 Ready。

11. 作为部署维护者，我希望更新镜像不重复初始化数据库，不改变现有业务数据。
12. 作为部署维护者，我希望失败保留诊断现场并停止 crash-loop，不报告未经验证的成功。

## 实现决策

- V037 是运行时兼容探测代号；V041 是社区定时任务迁移基线。完整首次初始化已包含对应结构，不重复执行迁移或导入全库 schema。
- 保留并恢复已有部署定制与整数类型兼容改动到版本化开发分支；当前基于上游创建的分支尚未包含这些本地提交。
- 元数据归一化集中在现有 schema 探测器内，不新增数据库厂商适配器或兼容开关。
- 仅消除 bigint、int、tinyint 的整数显示宽度；signed/unsigned、字符长度、decimal 精度不变。
- 仅对 datetime(3) 字段归一化 CURRENT_TIMESTAMP 与 CURRENT_TIMESTAMP(3) 的已确认等价展示；实际字段类型和 ON UPDATE 契约不放宽。
- 对指定幂等键生成列，继续验证 varchar(137)、可空、STORED GENERATED 及批准的生成表达式。普通默认值为空时沿用 MySQL 行为；默认值非空时，只有其规范化表达式与 GENERATION_EXPRESSION 一致才允许重复投影，不接受任意非空默认值。
- 未知元数据、权限不足、查询失败、实际结构不匹配继续按现有严格规则处理。禁止伪造 V037_READY 或关闭能力门禁。
- 能力接口及前端契约不变：available=true、mode=V037_READY、clusterReady=true、reason=null 才展示入口。Scanner 开关决定后台扫描，不替代上述模块可用性判定。
- clusterReady 是发布流程对全部 serving 节点的外部证明，不由本机 schema 自动推断。
- 在既有 Scheduled Task 运维文档中补充兼容边界，不新增 ADR 或 CONTEXT 文件。
- 使用已有 linux/amd64 镜像离线传输流程更新现有应用，不修改外部数据库、Redis 或 MinIO 持久化数据。
- 只推送审查后的源码、测试、文档和必要部署文件到用户确认的公开关联 fork 开发分支，不自动创建 PR，不发布真实环境文件、密钥、日志、镜像归档或本地运行状态。

## 测试决策

- 测试接缝沿用探测器公开的 detect/inventory 与现有模拟 JDBC 元数据夹具；断言最终能力及缺失对象，而不是私有方法实现。
- 正例覆盖 MySQL 8 标准元数据和 OceanBase 实测元数据，完整结构均应为 V037_READY、SOURCE_AWARE、scheduledAvailable=true、missingObjects 为空。
- 反例覆盖整数无符号属性缺失、varchar 长度变化、datetime 精度变化、错误或常量默认值、缺失 ON UPDATE、生成列默认值与表达式不一致、错误生成表达式、错误索引顺序与唯一性、元数据查询异常。
- 先运行相关回归测试验证修复前失败、修复后通过，再执行完整 Maven/镜像构建；任何跳过或环境阻塞均如实报告。
- 部署后核验实际运行镜像、启动日志和容器稳定性，不能仅以进程存活或 /checkpreload.htm 返回成功判断定时任务可用。
- 使用已有登录态 BrowserSkill 捕获能力接口真实响应并观察“定时任务”菜单；不提取认证秘密，不创建或执行任务。

## 不在范围内

- 新增或改变定时任务业务功能、前端门禁、API 鉴权或响应结构。
- 重新导入 schema、重复执行 V041、删除或改写既有数据库数据。
- 为一次兼容修复引入 OceanBase Testcontainer、新框架或通用元数据适配体系。
- 任意数据库版本的全面兼容声明；本次范围是 MySQL 8 既有行为与已实测 OceanBase 4.3.5.6 元数据表示。
- 自动回滚、创建 Pull Request、合并到 master、向上游推送。
