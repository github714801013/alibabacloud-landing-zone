# 已绑定工单改派切换数字人同步切换 SDLC 规格

- 任务标识：`workitem-sdlc-switch-on-reassign`
- 确认日期：2026-11-07
- 状态：澄清已定稿，测试接缝与二次开发耦合方式已确认，可进入实现
- 依据：用户“出需求来改这个逻辑，太难用了”；Q1–Q11 均按推荐确认；用户补充“这次改造要用二次开发角度进行审核”

## 问题说明

工单首次交付时会按目标数字人绑定 SDLC。此后把工单改派给另一名数字人，交付虽然会按 stop-then-start 重启，但流程仍取工单已存的旧 SDLC，只把当前步骤重置回旧流程首步。结果是新数字人执行的是上一名数字人的流程，与“交接后由接手人按自己的流程继续”的直觉不一致；会话内通过 MCP 交付同样如此，用户无法从交付结果看出流程没有切换。

## 解决方案

已绑定 SDLC 的工单改派给**不同**数字人时，按目标数字人当前生效版本重新解析 SDLC，切换工单绑定并取新流程首步重新开始交付。同一数字人重派、目标流程与当前相同、目标解析不出流程或流程无步骤时，不切换，继续按旧流程重启，交付不中断。前端在提交前展示目标流程名与“从首步重新开始”的提示，切换流程时二次确认。实际发生切换时写入工单审计事件，并在统一时间线展示旧流程与新流程。

已绑定工单通过 MCP 交付时，请求中的 `sdlcId` 继续被忽略；换绑结果只由目标数字人决定。真人改派、首次绑定、数字人运行中互接手、评论返工换绑均保持既有行为。

2. 作为工单负责人，我希望切换后从新流程首步重新开始，而不是停在旧流程的中间步骤。
3. 作为工单负责人，我希望改派给同一名数字人时流程保持不变，避免无意中重置交付。
4. 作为工单负责人，我希望目标数字人的流程与当前流程相同时只重启交付，不产生“切换”记录。

11. 作为工单负责人，我希望设置了未来开始时间时，流程立即切换，但交付到点才启动，且启动的是新流程首步。
12. 作为澄清会话中的用户，我希望通过 MCP 把工单交付给另一名数字人时，流程同样自动切换，不需要额外操作。
13. 作为澄清会话中的用户，我希望 MCP 请求里误传的 `sdlcId` 不会覆盖目标数字人的流程。
14. 作为工单负责人，我希望把工单改派给真人时流程保持不变。

17. 作为工单负责人，我希望选择当前同一名数字人时看到“流程不变”的提示，而不是切换提示。
18. 作为工单负责人，我希望首次交付时不出现换流程提示，保持原有交互。

20. 作为工单负责人，我希望能在时间线上看到“交付流程已切换”以及旧流程和新流程，便于解释交付为何从头开始。
21. 作为审计人员，我希望只有实际发生流程切换时才产生切换事件，同人、同流程、回退和真人改派都不产生。
22. 作为维护者，我希望本次改动只落在声明的上游文件与符号，新增能力可识别为本地定制，后续同步上游时可重放或移除。
23. 作为维护者，我希望中英文界面与后端文案同时更新，不出现单语缺失。

## 实现决策

### 触发与判定

- 只在工单已绑定 SDLC 且已有当前步骤、目标经办人为数字人、且经办人实际发生变化时，重新解析目标流程。
- 同一数字人重派：不重新解析，保持旧流程首步重启。
- 真人改派：不进入流程解析。
- 解析结果与当前流程相同：不写 `sdlc_id`，只重置首步并重启。
- 解析结果不同且新流程有首步：写回新 `sdlc_id` 与新首步，再以新首步触发重启。
- 解析失败、无首步、目标数字人跨租户或异常：不换绑，回退旧流程首步继续重启；跨租户仍按既有错误回滚。

### 解析口径

复用现有“目标数字人流程解析”原子，与首次绑定、数字人互接手保持同一口径：生效版本优先；生效版本解绑不回落历史版本；无生效版本才取任一版本；仍为空时取工作类型默认流程；首步取最小 `stepOrder`。

### 写回与并发

复用既有流程与当前步骤的乐观锁写回，版本冲突时整个改派事务回滚。不修改状态节点、经办人字段或重启协议；不下发数据库结构变更。

### 事件与展示

- 仅实际切换时写入流程切换事件，事件值为旧、新流程名称，明细记录旧、新流程 id 与操作者。
- 统一时间线新增系统项文案，中英文成对；不展示原始流程 id 作为用户文案。
- 未切换场景不写该事件；既有经办人变更事件不变。

### 前端交互

- 交付弹窗在小队成员数据可用时展示目标流程名。
- 目标流程不同：提示“将切换到 <流程名> 并从首步重新开始”，提交前二次确认。
- 目标流程相同但换了人：提示“流程相同，将从首步重启”，不弹切换确认。
- 选中当前同一数字人：提示“同一数字人，流程不变”。
- 目标成员无流程：提示“未配置流程，将沿用当前流程”。
- 首次交付：不展示换绑提示与确认。
- 小队成员加载失败：不展示流程名，不阻塞提交；提交请求不新增 `sdlcId` 字段。

### 接口与兼容

- REST 改派接口与 MCP 交付工具的出入参不变；已绑定工单的 `sdlcId` 继续忽略。
- MCP 人工凭据与数字人派发凭据收敛到同一服务方法，会话交付与页面交付行为一致。
- 不新增配置键、不新增数据库表或字段、不改变权限模型。

### 二次开发边界

- 复用上游稳定符号完成解析与写回，不复制上游实现。
- 对上游核心服务只增加一个局部钩子与一个事件文案分支，不做相邻重构、不全局格式化、不改公开接口。
- 若实现阶段评估认为需要把规则进一步隔离到本地新文件，按二次开发改动面文档登记的耦合方式执行，不静默扩大范围。

## 测试决策

好测试只验证外部行为：给定工单、数字人、流程数据与改派请求，断言工单绑定的流程、当前步骤、事件行与接口结果；不测私有方法或内部调用顺序。

复用既有接缝，不新增测试框架：

1. **改派服务接缝**：验证不同数字人切换、同人不切、同流程只重启、解析失败回退、无步骤回退、真人改派、跨租户回滚、版本冲突回滚。既有同类用例覆盖重启分支，新增用例沿用同一 mock 方式。
2. **流程解析接缝**：验证生效版本优先、解绑不回退、无生效版本取任一版本、默认流程回退、首步取最小 `stepOrder`。既有解析器测试可扩展。
3. **时间线接缝**：验证切换事件写入、未切换不写、统一时间线文案包含旧、新流程名。
4. **交付弹窗组件接缝**：验证不同流程提示与二次确认、同流程提示、同人提示、首次交付不提示、成员加载失败不阻塞提交；沿用既有组件测试与 i18n 断言方式。

不新增接缝；四类测试均落在既有公开边界上。测试数据基线见 `docs/engineering/plans/workitem-sdlc-switch-on-reassign-测试数据.md`，验收编号见同名验收清单。

## 不在范围内

- 数字人运行中互接手（HandoffService）的换绑行为。
- 评论触发的交互返工换绑。
- MCP 交付工具的参数语义调整；已绑定工单的 `sdlcId` 仍忽略。
- SDLC 停用状态校验与停用流程的绑定限制。
- 重启编排协议、任务包组装、执行器侧流程快照。
- 工单状态流转、权限模型、数据库结构、对外接口契约。
- 前端新增流程选择器；用户不能手动指定目标流程。
